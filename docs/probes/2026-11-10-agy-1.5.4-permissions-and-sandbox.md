# agy 1.5.4: permissions, sandbox, bypass and hooks (2026-11-10)

Profiles were passed with `--settings` and checked first with `agy --settings <file> -p=/config`,
which shows the effective config without spending a model turn. `--settings` accepts
`toolPermission`, `enableTerminalSandbox` and `unsandboxed(...)` rules as well as
`command`/`write_file` rules. The `--sandbox` flag alone doesn't show up in `/config`.

## `--settings` permissions

Profile `{"permissions":{"allow":["command(date)"],"deny":["write_file(*)"]}}`:

| Probe | Prompted | Finding |
|---|---|---|
| `date` | no | `--settings` permissions apply |
| `date -u` | no | `command(x)` is a prefix match; arguments pass |
| `date; touch f` | yes (offered to allow `touch`) | compound commands are split and each part checked |
| `date && touch f` | no, but only because `touch` had been allowed for the conversation one step earlier | `&&` is split like `;` |
| `date \| tee f` | yes (offered to allow `tee`) | pipes are split too |
| `ls` (allowed only in global settings) | yes | `--settings` permissions **replace** the global list, not merge: the profile is the whole policy |
| `whoami` | yes | baseline |
| file tool writes `notes.txt` | denied, no prompt | `write_file(*)` blocks the file tool ("Matches user-configured deny rule") |

`write_file(*)` covers only agy's file tool. The shell is a second write channel (`touch`, `tee`,
redirects, `sed -i`, ...).

## The sandbox

With `toolPermission: proceed-in-sandbox` and `enableTerminalSandbox: true`, **nothing prompted**, and:

| Action | Result |
|---|---|
| write in the workspace (`touch`, `echo > f`) | blocked, **even with no deny rule**: the sandbox makes the workspace read-only |
| write outside the workspace | blocked |
| read outside the workspace (`ls ~/code/tmp`, `~/.gitignore`, `~/.docker/config.json`) | blocked |
| network (`curl https://example.com`) | blocked (DNS fails) |
| loopback TCP (`httptest` servers) | blocked: `connect: operation not permitted` |
| Docker socket (`docker ps`) | blocked: `permission denied ... /var/run/docker.sock` |
| `dip` (rbenv shim) | blocked from executing at all |
| `git status`, `python3 -c`, `go vet ./...` | ran (the Go toolchain reaches its caches outside the repo) |
| `go test ./...` in apix | ran, but the 3 packages using `httptest` failed on loopback |

Allow rules do **not** take a command out of the sandbox: `command(go test)` still ran sandboxed.
(1.5.5 changed the first row: [the workspace became writable](2026-11-11-agy-1.5.5-live-probe.md).)

## Bypass

agy can ask to run a command outside the sandbox ("Allow sandbox bypass for command execution? ...
full network and disk access"). The prompt offers run once, always allow for the conversation, or
persist. Persisting writes `unsandboxed(<prefix>)` to the global `settings.json`. A profile with
`unsandboxed(go test)` then gave:

| Command | Bypass requested | Result |
|---|---|---|
| `go test -count=1 ./cmd/apix/` | no | ran **inside** the sandbox (`BypassSandbox: false`), FAIL on loopback |
| `go test -count=1 ./internal/pipeline/` | yes | ran **outside**, approved without a prompt: `ok` |

The short prefix matches, `--settings` carries the rule, and the rule approves but does not force a
bypass. agy's startup warning called `unsandboxed(...)` rules **deprecated** and said to migrate
them to `command(...)`, but `command(...)` rules don't bypass. (They were removed in 1.5.6: see
[the 2026-11-12 live check](2026-11-12-agy-1.5.6-claude-2.1.322-live-check.md).)

Ruby apps: `dip rspec` (Docker + dip) can't run in the sandbox at all, only bypassed.

## `PreToolUse` hook contract

A `PreToolUse` hook on `run_command` must return an explicit decision: `"decision": ""` and `{}` both
**deny** the call. `{"decision":"ask"}` defers to the normal flow (no prompt under
`proceed-in-sandbox`), so it's the pass-through. Tool args seen by the hook: `CommandLine`,
`WaitMsBeforeAsync`, `toolSummary` (no `BypassSandbox` key unless one was requested).

**Forcing a bypass.** `{"decision":"allow","overwrite":{"BypassSandbox":true}}` turns the call into
a bypass request. With a matching `unsandboxed(...)` rule it runs outside the sandbox without a
prompt (loopback test passed). **Without the rule, agy still prompts for the bypass**: hook `allow`
does not approve it. Both are needed.

**`dip rspec` through a bypass.** In a Ruby app with `unsandboxed(dip rspec)` and a requested
bypass: no prompt, containers started, `5 examples, 0 failures`, `git status` clean afterwards
(`coverage/` is gitignored). The command still exited 2, because SimpleCov's minimum coverage fails
on a single-file run, so a partial run is judged by the examples/failures line, not the exit code.

## `SessionStart` and `/new`

`SessionStart` fires for the new conversation, with its new `conversationId`, when the first message
after `/new` arrives, just before the first `PreInvocation`. Between `/new` and that message the old
ID is still current, so a ring in that window goes to the old conversation.

## Customizations from an `--add-dir`

From an added dir, agy loads `.agents/hooks.json`, `.agents/rules/AGENTS.md`, a root `AGENTS.md`,
`.agents/skills/<name>/`, and plugins under `.agents/plugins/<name>/` with their own hooks, rules
and skills (plugin skills are namespaced `<plugin>:<skill>`). Checked with print-mode `/hooks`,
`/skills` and `/plugin list` (no model turn), and for rules with marker words agy reported from
context, with no tool calls in the event stream.

## Other facts

- Config: `~/.gemini/antigravity-cli/settings.json` (permissions `allow`/`deny` with `command(...)`
  rules, `trustedWorkspaces`); shared hooks in `~/.gemini/config/hooks.json`; per-workspace hooks in
  `<workspace>/.agents/hooks.json`.
- Hook events: `SessionStart`, `PreToolUse`, `PostToolUse`, `PreInvocation`, `PostInvocation`, `Stop`.
  Command hooks only, JSON on stdin and stdout, 30 s default timeout, synchronous, run via `sh -c`
  with the directory holding `hooks.json` as cwd. Docs ship in the binary's builtin skill:
  `~/.gemini/antigravity-cli/builtin/skills/agy-customizations/docs/hooks.md`. Every payload carries
  `conversationId`, `lastUserInput`, `hookEventName` and `cwd`.
- Messages typed while agy is busy are queued ("Send Immediately" queue mode exists).
- `agy -p "/hooks"` and other read-only slash commands answer without spending a model turn.
- agy hooks run synchronously and block the loop, so a blocking wait in a hook would freeze the TUI.
