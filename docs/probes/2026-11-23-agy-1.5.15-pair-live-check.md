# agy 1.5.15: an agy + agy pair through tandem, live (2026-11-23)

The live check for same-harness pairs: two real agys launched by `tandem agy`, run on a small task
until `done`. The repo was a scratch git repo with `greet.py` and one test. The session was made with
`tandem init --task … --test-cmd 'python3 -m unittest'` and a scratch `TANDEM_HOME`; its brief asked
for `greet("Ann") == "hello, Ann!"` and a `ValueError` on an empty name. Each agy ran in its own
agterm pane:

```
tandem agy --role driver                                     # Gemini 4 Neon (High), the default
tandem agy --role navigator -- --model gemini-3.8-flash-high # while the driver ran
```

## The pair works end to end

- **Claims.** The first launch swapped the roles (`role_claimed … role=driver was=navigator`). The
  second made the pair instead of swapping back, and printed the pair note. `session.json` held
  `roles: {driver: agy, navigator: agy}` with one claim per role, each with its own agy's pid.
- **Per-role files.** `peers/driver/` and `peers/navigator/` each got their own `profile.json`,
  `.agents/`, `conversation_id`, `last_input`, `watchdog`, `watch.pid` and `watch.log`. The session
  dir root had no `.agents/`. Each agy started with its own role's initial prompt and protocol.
- **Doorbells.** The driver's watcher rang only `2ea0f67d…` (messages #0002, #0004, #0006 and
  #0008) and the navigator's only `1afb6e86…` (#0001, #0003, #0005, #0007 and #0009). These were
  the ids in each role's `conversation_id`. No ring was lost: every message got its reply without a
  nudge.
- **The task.** The two agys went through plan, review, one step and the three final review phases.
  The driver then sent `done` (#0011). The diff was the requested change plus a whitespace-only
  test, and both lived only in the repo. No `hooks.log` was written.
- **Relaunch.** The navigator quit, and its watcher logged `exiting: agy language server gone`. A
  plain `tandem agy` (no `--role`), run while the driver was still running, took the navigator role.
  It got a new conversation and a watcher that started on the first try.
- **Write gate.** The relaunched navigator was asked to run `touch gate-check.txt`. Its
  `PreToolUse` hook, which runs with `TANDEM_ROLE=navigator` in a session where agy holds both
  roles, turned the command into a prompt with `Reason: tandem write gate: this looks like a write
  (touch), and the navigator doesn't change files`. The prompt was cancelled, and the file was never
  created.

## Found: the navigator ran in Auto mode

agy 1.5.7 changed the default `Agent Mode` from Default to Auto ("sessions with no saved mode …
now start in Auto wherever Auto mode is available"). tandem passed `--mode` only to the driver, so
the first navigator's status bar read `auto · Gemini 3.8 Flash`. That was with
`enableTerminalSandbox: false` in its profile, which in 1.5.6 had made Auto unavailable (see the
2026-11-12 live check). In Auto:

- The navigator's commands ran in the sandbox. Its first `tandem watch --detach` failed, and the
  model spent a turn on "Investigating Sandbox Restrictions" before a second attempt ran.
- Auto's reviewer can approve commands that aren't on the navigator's allowlist. The `deny` rules
  and the `PreToolUse` write gate still apply, but the allowlist no longer decides alone.

The fix: both profiles set `"agentMode": ""`, which is what `/config` saves for Default. The
driver's `--mode accept-edits` still overrides it. With the fix, the relaunched navigator's status
bar showed no mode (Default), and its watcher started on the first try. This isn't specific to
pairs: any agy navigator on 1.5.7 or later started in Auto.

## Also found: a misleading pair note

The second launch printed `launch the driver with \`tandem agy --role driver\`` while the driver
was running. The note now names the other launch only when the other role isn't running.

## Not a problem

`tandem recv` with an empty inbox exits 3 by design, so agy shows those calls as `failed`. Both
agys took that as "no mail".
