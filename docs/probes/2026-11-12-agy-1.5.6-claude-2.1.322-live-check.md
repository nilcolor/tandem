# agy 1.5.6 and Claude 2.1.322: end-to-end live check (2026-11-12)

Plan Task 17, run interactively in agterm against a throwaway clone of apix (`go test ./...`). Four
sessions: `live-check` (Claude driver, agy navigator), `live-flip` (agy driver, Claude navigator),
`live-recheck` (the same flip, after fixes) and `live-cwd` (agy navigator alone). Each finding below
is followed by what tandem changed.

## agy 1.5.6 removed `unsandboxed(...)` rules

`tandem agy` on the then-default sandboxed navigator profile. The self-check passed (`check=ok`),
with the "unverified on 1.5.6" note.

- The TUI opened with `Invalid "unsandboxed" permission rules found; they are ignored and grant
  nothing:`, listing the profile's six rules. It named `~/.gemini/antigravity-cli/settings.json` as
  their file although they came from `--settings`. The binary says `unsandboxed is no longer a valid
  rule, use command() instead`, and its tool docs say `BypassSandbox: true` "Requires manual user
  approval".
- Every hook-forced bypass prompted: `tandem watch --as navigator --detach` and `tandem recv` both
  asked "can I run this command".
- The self-check couldn't see it: `/config` still echoes the rules, and print mode shows no warning.

Changed: from 1.5.6 (`UNSANDBOXED_REMOVED_IN`) the navigator gets the fallback profile with a
one-line note, and no self-check runs. (Later the same day tandem dropped agy before 1.5.6 altogether, and with
it the sandboxed profile, the self-check and `--profile`; see `docs/design.md`.)

## Fallback navigator, Claude driver (`live-check`)

- Watcher start, `tandem recv`/`send`/`status` and multi-line single-quoted sends ran with no prompt.
- The write gate: `touch x` got a prompt showing `tandem write gate: this looks like a write
  (touch), and the navigator doesn't change files`. (Asked plainly first, the navigator refused on
  its own, citing the protocol.)
- Doorbell both ways while idle: agy woke on the plan and the review request; Claude woke through
  its asyncRewake Stop hook on agy's reviews.
- Quitting agy: the watcher logged `exiting: agy language server gone`; a relaunch started a new one
  through `SessionStart`.
- `ANTIGRAVITY_LS_ADDRESS` in a `run_command` child is `localhost:<port>` (`localhost:64249`).
- `tandem recv` exiting 3 (no mail) shows as "failed" in agy's TUI.
- The `PreInvocation` hook recorded the initial `tandem:` prompt and the conversation id while the
  workspace trust prompt was still on screen.
- `tandem done` (after the user confirmed in Claude's console) wrote `summary.md`, cleared the repo
  pointer and ended the watcher.
- **An asyncRewake wake reaches Claude's `UserPromptSubmit`** as a `<task-notification>` block
  carrying the doorbell in a `<system-reminder>`, and was logged as human input. Changed: the prompt
  hook skips it.
- **The navigator prompted on read-only commands off the allowlist**: `git -C <abs repo> diff`,
  `make -C … help`, `go tool cover -func=<abs path>`. Changed: the fallback profile also allows
  `git -C <repo> status|diff|log|show`. (See the working directory below for why it used `-C`.)
- Claude ran in the user's auto mode, so this run didn't prove its `Bash(tandem … *)` rules.

## agy driver, Claude navigator (`live-flip`)

- `tandem agy --role driver` and `tandem claude --role navigator`, launched in the same second, both
  claimed their roles under the session lock.
- Driver watcher, `tandem recv`/`send` and `tandem done` ran with no prompt. Claude, in manual mode,
  ran its `tandem …` commands with no prompt.
- `tandem human`: a message to the navigator woke it, and its escalation reached the REPL 11 s later.
- **`--mode auto` didn't take**: agy's log said `--mode: overriding agent mode to auto`, then `auto
  mode is unavailable, falling back to default`. Auto mode needs the terminal sandbox, which the
  driver profile turns off. Every edit asked, `plan.md` and `decisions.md` too. Changed: drivers
  launch with `--mode accept-edits`, plus `write_file(<session dir>/plan.md)` and
  `write_file(<session dir>/decisions.md)`, which `accept-edits` alone doesn't cover (outside the
  workspace).
- **After `/new` the watcher rang the old conversation.** `/new` fires no hook, so
  `peers/agy/conversation_id` still named it; `agentapi` accepted the ring and the old conversation
  answered in the background, out of sight. agy holds exactly one
  `~/.gemini/antigravity-cli/presence/<conversation>.lock` open per process and moves it on `/new`
  (`lsof -p <agy pid>`). Changed: the watcher finds the agy pid above itself at `--detach` time and
  rings the conversation whose lock that pid holds.
- **agy runs commands in the session dir**: `pwd` printed `~/.tandem/sessions/apix--live-flip`.

## After the fixes (`live-recheck`, `live-cwd`)

- `accept-edits` took (agy's log: `overriding agent mode to accept-edits`, no fallback);
  `plan.md`, `decisions.md` and the Makefile were edited with no prompt.
- The watcher logged `agy is pid 15939; ringing the conversation it shows`. After `/new` it rang the
  new conversation from its lock while the hooks' file still named the old one.
- **A conversation with no turn yet doesn't act on a ring.** agy's log shows `SendAgentMessage`
  accepted, then no model call. After the user typed `hi`, agy read the waiting mail and replied;
  the next ring was answered in 15 s. After `/new`, type something once.
- The fallback navigator's `tandem done` got the write gate's prompt.
- **The working directory, again**: `pwd` stayed the session dir
  - with the protocol naming the repo and telling agy to use it;
  - with a second `--add-dir <repo>`, before or after the session dir: the conversation lists the
    session dir as its first workspace root either way;
  - with a `PreToolUse` `overwrite` setting `Cwd` to the repo: agy reported "A pre-tool hook changed
    the arguments of this tool call before it ran. Changed: Cwd." and ran it in the session dir
    anyway. The model leaves `Cwd` out of `run_command` (`{"CommandLine":"pwd",
    "WaitMsBeforeAsync":5000,…}`), and agy says its `run_command` takes no `Cwd`.
  - `cd <repo>` then `pwd` as two commands: each command gets a new shell.

  Changed: the protocol has agy run repo commands as `cd <repo> && <command>`. Live:
  `cd <repo> && go test ./...` and `cd <repo> && git diff` ran with no prompt on the fallback
  navigator (agy splits the compound command; `cd` is on its own system allowlist).
