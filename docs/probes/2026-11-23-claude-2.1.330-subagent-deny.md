# Claude Code 2.1.330: a subagent keeps the session's `--settings` deny (2026-11-23)

Question: does a subagent started with the Agent tool keep the `Edit`/`Write`/`NotebookEdit` deny
that `tandem claude --role navigator` passes with `--settings`? If it doesn't, a navigator fanning
the final review's lenses out to subagents could edit through them.

Setup: two fresh git repos, `claude -p --model sonnet --permission-mode acceptEdits --settings
<file>`, the same prompt in both: spawn a `general-purpose` subagent that lists its tools, then
creates `probe.txt` with the Write tool (else Edit or NotebookEdit, never Bash). `acceptEdits`
lets a write through without a prompt, so only the deny can stop it.

| Settings | Subagent's tools | `probe.txt` |
|---|---|---|
| `{"permissions": {"deny": ["Edit", "Write", "NotebookEdit"]}}` | Agent, Bash, Read, Skill, ToolSearch, … ; no Write, Edit or NotebookEdit, and `ToolSearch select:Write,Edit,NotebookEdit` found none | not created |
| `{"permissions": {}}` (control) | Agent, Bash, Edit, Read, Write, … (NotebookEdit deferred) | created by the subagent |

Result: the deny reaches subagents. A bare tool name in `deny` removes the tool from the
subagent's context too, as it does for the main session
([permission rules](2026-11-11-claude-permission-rules.md)). The subagent keeps Bash, as the
navigator does (`docs/backlog/claude-navigator-bash-can-write.md`), so fanning out adds no write
channel the navigator doesn't already have.
